## Where each task is evidenced

### Task 1 — Production Deployment

- **1.1** Frontend and backend both live on the public URLs above, no build or
  runtime errors.
- **1.2** PostgreSQL on Supabase, read and written by the deployed application.
  Registering an account writes a row you can see in the admin user list.
- **1.3** HTTPS, CORS, Helmet, and rate limiting all active on the deployed
  backend. Rate limiting returns `429` after 20 requests to `/api/auth/login`.
- **1.4** Health endpoint above, monitored by UptimeRobot every 5 minutes, with
  the public status page linked above.

### Task 2 — Cloud Preparation

- **2.1** [Architecture diagram](docs/30903180103559-ShopSphere-architecture.svg)
- **2.2** [Cloud service classification](docs/30903180103559-ShopSphere-cloud-service-classification.md)
- **2.3** [Namespace simulation evidence](docs/30903180103559-ShopSphere-namespace-simulation-evidence.md)
  · manifests in [`k8s/`](k8s/)

### Task 3 — Application Modernization

- **3.1** Review service deployed at its own URL above. The review routes are
  gone from the main API — `https://shopsphere-store-api.vercel.app/api/products/workspace-hub-8/reviews`
  returns `404`, while the same path on the review service returns `200`.
- **3.2** Reviews on any product page are fetched from the review service.
- **3.3** Serverless cleanup job, deployed and scheduled daily.
- **3.4** [Architecture decision record](docs/30903180103559-ShopSphere-architecture-decision-record.md)
