## Where each task is evidenced

### Task 1 — Production Deployment

- **1.1** Frontend and backend both live on the public URLs above, with no build
  or runtime errors. Every one of those URLs is checked by the pipeline's smoke
  job on each release.
- **1.2** PostgreSQL on Supabase, read and written by the deployed application.
  Registering an account, or adding an item to a cart, writes a row you can see
  in the admin dashboard.
- **1.3** HTTPS, CORS, Helmet, and rate limiting all active on the deployed
  backend. Rate limiting returns `429` after 20 requests to `/api/auth/login`.
- **1.4** Health endpoint above, monitored by UptimeRobot every 5 minutes, with
  the public status page linked above.

## A note on names

Every submitted document, the repository, and this file carry the required
`30903180103559-ShopSphere` name. The review service and the scheduled job are
independently deployed codebases **inside** that repository, in
[`review-service/`](review-service/) and [`jobs/`](jobs/), each with its own
`package.json`, its own dependency tree, and its own Vercel project — so they
are separate deployments living under the one required project name.

The storefront was built in the first semester under the working name
*DECI.Project*, and some seeded product data and e-mail templates still carry
it. The platform, the repository, and every submitted document are ShopSphere.
